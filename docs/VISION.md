## 一句话愿景

Tickbird 是一款原生 macOS 只读观察器：它把 Claude Code、Codex 等不同编码 Agent 的原始会话，整理成一条安静、可信、可追溯的工作轨迹，让用户在运行中看清过程，在完成后快速理解和验收结果。

核心体验不是“再做一个更漂亮的聊天窗口”，而是：

> 走开几分钟，回来几秒钟看懂；需要深究时，每个结论都能回到它之前的可观察过程。

## 产品角色

### 它是什么

- 跨 harness 的本地 session viewer。
- 常驻在工作区旁边的过程提纲。
- 按需展开的回答、证据和 diff 阅读器。
- 对 Agent 原始记录进行确定性整理的 trace viewer。

### 它不是什么

- 不是新的 Agent harness。
- 不是终端或 IDE 的替代品。
- 首版不提供输入、批准、继续或通用 Stop。
- 不替 Agent 重写最终回答。
- 不凭空补写 Agent 没有表达过的推理和因果关系。
- 不把历史 session 做成需要人工维护的收件箱。

## 核心原则

1. **App 可以自动更新内容，但不能仅因后台状态变化而改变用户当前所在的位置。**
2. **Agent 负责表达，App 负责整理事实和证据。**
3. **忠实重建可观察过程，不补写 Agent 没有表达的逻辑。**
4. **所有原始 action 都可追溯，但默认只展示可读的叙事主干。**
5. **左栏负责浏览和选择，右栏负责显示所选内容的完整详情。**
6. **最新状态优先，旧状态作为轻量历史存在。**
7. **默认安静；错误可以明显，普通完成不制造未读负担。**

## 信息层级

```text
项目
└── Session
    └── Turn
        ├── 过程轨迹
        ├── Turn 结果
        └── 原始事件与证据
```

- 项目是工作集合。
- Session 是 minimap 的边界；不同 session 不拼成伪连续时间线。
- Turn 是主要阅读单位：一个用户要求，以及 Agent 为它做的所有工作和最终结果。
- Tool call、result、thinking、文件变化等是 turn 内的可观察事件。

## 窗口模型

```text
常驻窄态  →  横向展开态  →  macOS 全屏态
 约 300px      约 1000px        用户主动进入
```

### 常驻窄态

- 只显示 turn minimap 和当前 turn 的过程轨迹。
- 不承担完整 Markdown、长日志或 diff 阅读。
- 窗口状态不会因 Agent 完成或出错而自动变宽。

### 横向展开态

- 原窗口朝屏幕内部横向展开，不另开一套界面。
- 左栏的宽度、内容、选中节点和滚动位置保持不变。
- 右栏显示 Turn 结果或当前所选节点的完整详情。
- 左右两栏独立滚动，通过选择、定位和高亮建立关系。

### macOS 全屏态

- 沿用系统原生全屏。
- 只提供更大的阅读与 review 空间，不引入新的信息结构。

### 窗口层级

- 默认是普通 macOS 窗口。
- 提供可选的“保持在最前”。
- 窄态与展开态分别记住尺寸和位置。

## 当前任务锚定

- 默认尝试识别最后一个处于前台的 IDE、终端、项目和 session。
- 点击 Tickbird 自己或切到无关应用时，保持上一个有效 session。
- 只有高置信度匹配时才自动切换；不确定时不猜测。
- 用户可以手动选择 session，也可以将当前选择固定，暂停自动跟随。
- 后台 session 的状态变化不会抢走当前视图。

## 项目与 Session 导航

- 第一屏只显示当前项目、正在运行的项目，以及最近活跃的少数项目。
- 其余项目进入“更多项目”。
- “更多项目”只需要按项目名快速过滤，不做完整历史搜索产品。
- 同一项目的多个 session 保持独立，通过顶部选择器切换。
- 后台 session 普通完成时使用中性状态点；出错时才使用明显颜色。
- 不显示需要清理的未读数字。

## Turn Minimap

历史 turn 不在过程栏中压缩成卡片或单行目录，而是从过程内容区彻底消失，只在最左侧留下极窄的 minimap 标记。

```text
┌──┬──────────────┬────────────────────┐
│· │ 当前 turn     │ Turn 结果或节点详情 │
│· │              │                    │
│· │ 过程主干      │                    │
│● │              │                    │
└──┴──────────────┴────────────────────┘
 ↑
Turn minimap
```

### 编码规则

- 纵向位置表示 turn 顺序，最早在上，最新在下。
- 每条刻度代表一个 turn。
- 刻度长度表示可观察的活动量，主要由真实 action 数量计算。
- 使用对数或分段缩放，避免极大 turn 压平其他差异。
- 耗时不参与刻度长度；文件增删量也不参与。
- 当前选中的 turn 使用更明显的刻度。
- 普通完成保持中性，错误才使用错误色。
- 最底部标出当前最新位置。
- Minimap 始终保留可见，不退化成只能猜到的隐藏热区；局部放大镜可以按需浮出。
- 少量 turn 从底部向上累积，避免 6 个刻度松散地铺满整条窗口。

本机真实语料（64 个 Claude Code session、4 个 Codex session）里，session 的 turn 数中位数为 6、p90 为 22、最大为 29。因此首要问题是让少量刻度清楚、安静，而不是优先为 80 / 200 个 turn 设计常态界面。极端压缩只作为未来 harness 的兜底。

### 局部放大镜

- 鼠标进入 minimap 后，在指针附近展开一个局部 turn 列表。
- 默认显示附近约 5 个 turn。
- 标题来自用户提问原文的第一句，不生成新标题。
- 可显示 `action 数量 · 耗时 · 文件数` 等客观信息。
- 点击后过程栏切换到对应 turn；右栏展开时同步切换。
- 极长 session 超过像素承载能力时，先显示密度带，再在局部放大镜中展开真实 turn。

## 过程轨迹

过程栏不是原始日志，也不是 App 生成的总结，而是一条可追溯的叙事主干。

```text
Agent 明确表达的意图
    ↓
工具调用或文件操作
    ↓
工具返回的观察结果
    ↓
Agent 明确写出的判断或转折
    ↓
下一组行动
    ↓
最终回答
```

### 默认主干

- Agent 的原话或可见说明作为叙事节点。
- 连续、相近的 action 确定性地合并成 action 组。
- 重复动作显示为 `×N`，但每次原始 action 仍可查看。
- 成功且重复的普通操作收拢。
- 失败、重试、方向变化始终露出。
- 子 Agent 作为可展开的嵌套分支。
- 普通屏幕一屏目标容纳约 10–14 个主要节点。
- Agent 原话和阶段节点较舒展，次级 action 摘要更紧凑。

### Thinking / Reasoning

- 默认显示一行原始内容预览和耗时。
- 预览来自原文，不由 App 重新总结。
- 没有可展示内容时退化为 `思考了 12s`。
- 点击后在右栏查看完整内容。
- 某个 harness 没有 thinking 时不补造这一层。

### 展开语法

- 左栏中的纵向 disclosure 只展开结构，例如 action 组里的文件或命令。
- 内容详情不在左栏向下铺开。
- 点击 thinking、tool result、文件、测试等内容节点，统一在右栏展示详情。

## Turn 结果与详情栏

右栏是一块按需出现的 detail surface。

### Turn 结果

- 保留 Agent 最终回答的原始结构和措辞，以舒适的 Markdown 排版呈现。
- 运行过程中逐渐累积真实有效的结果，例如测试状态、截图和文件变化。
- 同一结果优先原地更新最新状态，旧状态进入轻量历史，例如 `曾失败 1 次`。
- App 不生成另一份重复的“智能总结”。
- 客观状态、完整回答和可验证证据共存，但不机械堆成仪表盘。

### 节点详情

- Thinking：完整原文。
- Tool call：完整输入与结果。
- 测试：完整输出、错误和历史运行。
- 文件：对应 diff。
- 截图：原始视觉结果。
- Agent 说明：原始 Markdown。

### 自动更新

- 新结果可以更新 Turn 结果，但不自动切走用户正在查看的详情。
- 用户不在滚动底部时，不强制拉回最新位置；只显示轻量的新内容提示。

## 详情 Tab 模型

右栏采用“固定结果 + 单个预览 + 用户固定”的 Tab 模型。

```text
[ Turn 结果 ] [ AuthService.swift ] [ 测试输出 ]
     固定            已固定             临时预览
```

- `Turn 结果` 永远存在且不可关闭。
- 单击过程节点，在一个临时预览 Tab 中打开。
- 继续单击其他节点时覆盖临时预览，不不断新增 Tab。
- 用户主动固定、双击或选择“保留”后，预览才成为正式 Tab。
- 同一资源已经打开时，定位到原 Tab，不重复创建。
- 同一测试从失败变为通过时更新原 Tab，不新建 Tab。
- Tab 按 turn 隔离；切换 turn 时显示该 turn 的 Tab，切回来恢复原状态和阅读位置。
- 超过可用宽度的固定 Tab 进入溢出菜单。
- 首版不支持把多个详情拆成并排面板。

## Diff 与 Review

### Diff 范围

```text
Turn diff  /  Session diff  /  当前 Git diff
   默认          可选              可选
```

- 默认显示所选 turn 的冻结 diff，回答“这个 turn 改了什么”。
- Session diff 聚合当前 session 的变化。
- 当前 Git diff 实时读取工作区，可能包含后续 session 或人工修改。
- 切换范围时尽量保持当前文件不变。
- 明确标注范围和时间，避免把历史快照误认为当前代码。
- 非 Git 项目仍可使用 turn/session diff。

### Diff 排版

- 横向展开时默认 unified diff。
- 足够宽或 macOS 全屏时，允许用户主动切换 side-by-side。
- 窗口变宽时不自动改变 diff 模式。
- 文件导航直接使用过程栏中展开的文件列表，不再增加一套右侧文件栏。

### Review 连续性

- 记住每个 diff 范围的当前文件和文件内滚动位置。
- 关闭右栏、切换 turn 或重启 App 后可以继续。
- 首版不提供“已 review”勾选、进度百分比或剩余文件数。

## 完成与闲置状态

- 新 turn 开始时，上一个 turn 的过程从内容区消失，只保留 minimap 刻度。
- Turn 完成后，当前内容停在原位，只更新完成状态。
- 所有 Agent 空闲时，继续停留在当前 session 和最后一个 turn。
- 不自动切换为跨项目“最近完成”页面。
- 最近项目和最近完成信息只在项目/session 选择器中按需出现。
- 最新项位于时间方向的底部。

## 搜索边界

- 不做全局对话搜索、复杂筛选和搜索结果页。
- 人负责浏览当前与最近，Agent 负责检索漫长历史。
- “更多项目”只保留项目名过滤。
- 后续如有高频需求，优先为外部 Agent 提供结构化记录接口，而不是给用户再造一个搜索系统。

## 控制边界

首版严格只读。

- 不提供通用 Stop、批准、继续或输入。
- 提供可靠的“返回 Agent”：激活对应终端或 IDE，并尽量定位项目和 session。
- 可以提供全局快捷键缩短“发现问题 → 回原 Agent 处理”的路径。
- 未来只有某个 harness adapter 能高置信度定位 session、优雅中断并确认结果时，才按能力显示 Stop；不承诺虚假的跨 harness 通用控制。

## 数据真实性与未来 Agent 增强

### 第一层：原始记录

保存 harness 产生的消息、tool call、result、文件变化、时间和父子关系，永不改写。

### 第二层：确定性整理

- 跨 harness 统一事件格式。
- 配对 tool call 与 result。
- 计算耗时、次数、成功失败和文件变化。
- 归并重复动作。
- 恢复分支、子 Agent 和 turn 生命周期。

这一层必须独立构成完整、快速、离线可用的产品。

### 第三层：可选 Agent 增强

以后可选择性增加：

- 阶段命名。
- 目标归纳。
- 因果关系连接。
- 重复尝试或异常路径提示。

增强层必须：

- 不改变原始顺序。
- 不删除或覆盖原始内容。
- 明确标识为 AI 整理。
- 每个判断能回到依据事件。
- 用户关闭后，基础产品仍然完整可用。
- 不在用户不知情时把本地记录发送给模型。

## 当前最需要验证的视觉原型

### 第一轮：核心阅读流

交互稿：`sidecar-core-flow.html`（本地原型 `sidecar-core-flow.html`，未共享）

这一轮已经初步确认：

- 常驻窗口在约 290–324px 宽时仍然可读；minimap 占 31–34px，其余空间只承载当前 turn。
- Prompt 最多显示两行；过程节点以“一行标题 + 一行客观元信息”为常态，Agent 原话允许自然换行。
- 错误只用一个克制的红色节点暴露；成功后的 `曾失败 1 次` 降为文字历史入口。
- 横向展开时左侧宽度和选中节点保持不变，右侧直接出现，不重排左侧过程。
- 窄态的“查看结果”只负责触发展开；展开后由固定 `Turn 结果` Tab 接管，因此入口不重复显示。
- 右栏采用“固定结果 + 已保留 Tab + 单个临时预览”的组合。普通点击替换临时预览，主动保留后才增加 Tab。
- `Turn 结果` 先安静地列出测试、文件变化等客观证据，再完整保留 Agent 回答；不做第二份智能总结，也不堆成仪表盘。
- 文件节点直接进入 unified diff；diff 范围属于右栏局部工具，不污染全局导航。

### 后续验证

1. unified diff 在普通展开宽度与 macOS 全屏下的可读宽度。
2. 普通完成、后台完成、错误和当前运行状态在项目/session 选择器里的克制程度。
3. 过程节点的确定性分组规则能否把真实 Claude Code 与 Codex session 稳定压到 10–14 个主节点。
4. 未来接入 turn 数明显更高的 harness 时，再验证密度带；它不再阻塞首版。

### 第二轮：v7 与常驻窗口融合

交互稿：`sidecar-companion-v8.html`（本地原型 `sidecar-companion-v8.html`，未共享）

v7 的确定性分组、跨 harness 降级、thinking 单行预览和节点详情分类予以保留；常驻视觉作以下修正：

- 视觉朝代码编辑器靠拢，保留 GitHub 与 Xcode 两套经过验证的语义色体系及其深浅模式；它们是完整映射，不混用色值。
- 普通叙事、thinking、action 标题和成功状态保持中性，不按节点类别把整行染色。颜色只落在有明确语义的局部：路径 token 使用 `sem-path`，工具名与结构化符号使用 `sem-tool`，错误使用 `sem-error`，等待、历史失败与捕获降级使用 `sem-warn`；当前选择使用独立的 `accent`。
- Agent 原话和 Prompt 属于“表达”，不做自动语法着色；机器输出、结构化标题与 diff 才使用编辑器式 token 和等宽字体。这样颜色提供定位线索，而不是把时间线画成彩虹。
- 不永久展示 `Exact`、projection rule、事件模型等工程信息。完整捕获是安静的默认，只有 `Partial` 或错误需要显露；原始事件进入更多菜单。
- Minimap 保持可见，并恢复“刻度长度 = 可观察 action 量”的编码，不做仅在屏幕边缘悬浮才出现的隐藏导航。
- 运行态只保留一个静态或极轻的状态点；取消底栏扫光、节点扫光和多处脉冲，避免常驻窗口持续吸引注意。
- Turn 头部只回答“在做什么、现在怎样”；测试、文件和历史失败作为一行次要元信息，不制造仪表盘感。
- `Turn 结果` 先呈现最新客观证据，再呈现 Agent 完整回答；运行中没有最终回答时明确留空，不伪装成已经完成。
- 右栏只有固定结果、一个临时预览和用户保留的 Tab；事件模型不是常驻一级 Tab。
- Agent 原话使用正文排版，thinking 与 action 使用更紧凑的声音；不依赖 8–10px 小字维持密度。
